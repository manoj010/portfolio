# Students Need Two Modes Of Learning

The AI-in-school debate keeps getting squeezed into two bad options.

Option one:

```txt
ban AI
```

Option two:

```txt
let students use AI for everything
```

Both are too simple.

Students need something more useful:

```txt
two modes of learning
```

One mode builds the mind without AI.

The other teaches students how to use AI without letting it replace the mind.

That sounds obvious.

It is also the part schools, parents, and software builders have to get right.

## The Fresh Signal

On September 6, 2026, [The Guardian published an essay by Daniel Susskind](https://www.theguardian.com/technology/2026/sep/06/daniel-susskind-father-studies-ai-artificial-intelligence-what-parents-need-know) arguing that parents and educators should prepare children for an AI-shaped world while still protecting foundational learning.

One useful idea in the piece is a "teach both, test both" approach, similar to how schools eventually handled calculators.

Students should learn with AI.

Students should also learn without AI.

Around the same moment, school systems have been drawing harder lines. [AP reported](https://apnews.com/article/647f6a968eea0399521b7934418b1aff) that New York City announced a one-year ban on student-facing generative AI tools for elementary and middle school students, while still planning AI literacy for older students.

The tension is clear:

```txt
AI is too useful to ignore
and too powerful to hand over carelessly
```

That is the real education problem.

## Why Ban-Only Fails

Ban-only policies feel clean.

They reduce cheating.

They protect younger students from overreliance.

They give schools time to think.

Those are fair reasons.

But a ban is not a curriculum.

If students only hear:

```txt
do not use AI
```

they do not learn:

- when AI is useful
- when AI is dangerous
- how to verify output
- how to spot hallucinations
- how to ask better questions
- how to cite sources
- how to protect private data
- how to keep their own thinking active

The world outside school will not ban AI for them.

So education has to prepare students for that world.

Not by handing them the tool too early for everything.

By teaching judgment.

## Why Use-Only Fails

The opposite approach is also weak.

If every assignment becomes AI-assisted by default, students may skip the exact struggle that builds skill.

Writing is not only producing paragraphs.

It is learning how to think through language.

Math is not only producing the answer.

It is learning structure, abstraction, and proof.

Coding is not only producing a working file.

It is learning decomposition, debugging, and cause-effect reasoning.

Reading is not only extracting a summary.

It is building attention, patience, memory, and interpretation.

If AI does all the friction, the student may get the product without developing the process.

That is the quiet danger.

Not that students become lazy.

That they become dependent before they become capable.

## Two Modes, Not One Rule

The useful model is simple.

Students should have assignments in two modes.

```txt
Mode 1: without AI
Mode 2: with AI
```

The first mode is for building core ability.

The second mode is for learning responsible tool use.

That is not hypocrisy.

It is training.

Athletes lift weights without machines controlling every motion.

Musicians practice scales before relying on production software.

Pilots learn instruments and procedures before autopilot becomes normal.

Students should learn the same way.

First build the internal ability.

Then learn the tool.

Then learn when not to trust the tool.

## Mode 1: Learn Without AI

Without-AI work should be explicit.

Not vague.

Not moralistic.

The teacher should say:

```txt
For this task, AI is off because the goal is to build the skill inside your own head.
```

Good without-AI tasks include:

- mental math
- handwritten proof steps
- first-draft writing
- close reading
- memory recall
- diagramming a concept
- debugging a small program manually
- explaining a topic out loud
- solving a problem on paper

The point is not nostalgia.

The point is cognitive muscle.

Some skills have to be slow before they become fluent.

If students never experience the slow part, they may not know what the tool is doing for them.

## Mode 2: Learn With AI

With-AI work should also be explicit.

The teacher should say:

```txt
For this task, AI is allowed because the goal is to learn how to use it responsibly.
```

Good with-AI tasks include:

- compare AI explanations
- ask AI for feedback on a draft
- generate practice questions
- find weak assumptions
- summarize a source, then verify it
- ask for multiple solution paths
- use AI to debug, then explain the fix
- improve structure without outsourcing the argument
- ask AI to challenge a position
- check citations against real sources

The key is that the student must remain accountable.

AI can help.

The student still has to understand.

## The Three-Verb Rule

A good AI assignment should require three verbs:

```txt
think
verify
explain
```

Think:

```txt
What do I believe before using the tool?
```

Verify:

```txt
Which parts of the AI output are true, sourced, and relevant?
```

Explain:

```txt
Can I describe the final answer in my own words?
```

If a student cannot explain the answer, the AI did the learning.

If a student can explain, critique, and improve the answer, the AI became a tutor, not a replacement brain.

That is the difference.

## Assessment Has To Change

Schools cannot solve this with AI detectors.

AI detectors are unreliable and easy to misunderstand.

More importantly, detection does not teach.

Assessment should instead make process visible.

For example:

- show the first attempt
- show the prompt used
- mark which AI suggestions were accepted
- explain which suggestions were rejected
- cite sources separately from the model
- include an oral explanation
- include in-class writing
- include a reflection on mistakes
- compare work with and without AI

This makes cheating less attractive because the grade is not only the final polished output.

The grade includes judgment.

And judgment is harder to fake.

## AI Literacy Is Not Prompt Tricks

AI literacy should not mean:

```txt
learn ten magic prompts
```

That is too shallow.

Students need to understand:

- models can be fluent and wrong
- answers depend on context
- sources matter
- private data should not be pasted casually
- generated text may need attribution
- bias can appear in outputs
- AI can over-optimize for sounding helpful
- tools have limits, costs, and owners
- human responsibility does not disappear

This connects to [Why Context Is Becoming More Important Than Prompts](/blog/why-context-is-becoming-more-important-than-prompts).

The future skill is not only wording a prompt nicely.

It is knowing what context to provide, what context to withhold, and how to judge the result.

## Technical Students Need This Too

This is not only for humanities classes.

Technical students need two modes even more.

In coding, AI can now generate useful drafts quickly.

That is good.

But students still need to understand:

- control flow
- data structures
- debugging
- tests
- security basics
- complexity
- architecture tradeoffs
- error messages
- how code fails in production

If a beginner lets AI write everything, they may ship code they cannot repair.

That is fragile.

I wrote in [Why AI Grew Fastest In Coding](/blog/why-ai-grew-fastest-in-coding) that coding is unusually compatible with AI because code has structure, feedback loops, and tests.

But that same compatibility can hide weakness.

The program may run.

The student may not understand why.

That is not learning yet.

## Non-Technical Students Need It Too

For non-technical students, AI can be an incredible explainer.

It can simplify a concept.

It can translate jargon.

It can create examples.

It can quiz the student.

It can help a shy learner ask questions without embarrassment.

That is powerful.

But it can also flatten thought.

If every hard reading becomes a summary, students may never build attention.

If every essay starts from generated prose, students may never find their own voice.

If every opinion is polished by a model, students may confuse fluency with depth.

So the rule should not be:

```txt
AI is forbidden
```

or:

```txt
AI is always fine
```

The rule should be:

```txt
What skill are we training today?
```

## Parents Need A Better Question

Parents often ask:

```txt
Should my child use AI?
```

A better question is:

```txt
What is my child using AI for?
```

There is a big difference between:

- asking AI to explain a confusing topic
- asking AI to solve the homework
- using AI to practice vocabulary
- using AI to write the whole essay
- asking AI to check a proof
- asking AI to replace reading

The same tool can support learning or bypass it.

The difference is the task design.

Parents do not need to become AI experts overnight.

But they can ask a simple follow-up:

```txt
Can you explain it back to me without the tool?
```

That one question catches a lot.

## Product Builders Have Responsibility

Education technology companies should not design AI tools as answer vending machines.

Good learning AI should encourage:

- hints before answers
- source checking
- step-by-step reasoning
- student explanation
- reflection
- limits by age
- teacher controls
- clear data rules
- mode switching

The interface should make it easy to say:

```txt
help me learn
```

instead of only:

```txt
give me the answer
```

That is a product design choice.

AI tutors should protect the learning loop, not quietly remove it.

## The Takeaway

AI is going to be part of education.

Trying to pretend otherwise is not realistic.

But letting AI absorb every difficult part of learning is also a mistake.

Students need two modes:

```txt
without AI
to build internal skill

with AI
to build judgment about the tool
```

Teach both.

Test both.

Make the student think, verify, and explain.

That is the path between panic and surrender.

Not banning the future.

Not outsourcing the mind.

Training people to stay intelligent while using intelligent tools.
